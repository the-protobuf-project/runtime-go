# Database

Durable records with a backend-agnostic contract, driven by protorm's generated
descriptors. One CRUD interface over SQL, document stores, key-value stores and
graphs; a driver implements what its backend can do and says so where it cannot.

| Backend | Package | Status |
| --- | --- | --- |
| PostgreSQL / MySQL / SQLite | [`database/orm`](./orm) | implemented (GORM) |
| MongoDB | [`database/mongodb`](./mongodb) | implemented |
| Redis | [`database/redis`](./redis) | implemented |
| ArangoDB | [`database/arangodb`](./arangodb) | implemented (documents + graph) |
| TimescaleDB | [`database/timescale`](./timescale) | implemented (SQL + time series) |
| Neo4j | `database/neo4j` | next |

For ephemeral, TTL-bound entries see [`cache`](../cache); for messaging see
[`streams`](../streams).

## Usage

Three steps, the same for every backend:

```go
client, _ := mongodb.NewClient(ctx, mongodb.Config{Address: "localhost:27017"})
defer client.Close(ctx)

p := mongodb.NewProvider(client)
db, _ := p.SetDatabase(ctx, "tenant_a")
defer db.Close()
```

The client is yours: a provider does not dial it and does not close it. Hand the
same one to the cache and streams layers and all three share a pool.

`SetDatabase` overrides `Resource.Schema` for every resource driven through the
result, which is what lets one set of generated descriptors serve many tenants —
the descriptor says what a Book is, the selection says whose.

## Your model comes from the proto

There are no Go model types here. A `Resource` descriptor — generated by
protorm, or built by hand — carries the columns, their kinds, the primary key,
which are unique and which the driver fills, and every driver reads records
through it via protoreflect.

```go
reg := database.NewRegistry(grpcx.Resources...)
res, _ := reg.Resource("Book")

db.Schema.EnsureSchema(ctx, res)      // CREATE TABLE / createCollection + indexes
id, _ := db.Create(ctx, res, book)    // book is a proto.Message
got, _ := db.Get(ctx, res, id)
```

`For` binds a driver and a descriptor to one message type, so the descriptor
stops being an argument on every call and reads stop ending in an assertion the
compiler cannot check:

```go
books, _ := database.For[*pb.Book](db, res)
b, _ := books.Get(ctx, "books/dune")   // already a *pb.Book
```

## What a backend cannot do

Backends are not equally capable, and the contract says so rather than
pretending. Each capability is an interface a driver implements only if it can;
[`Build`](./provider.go) resolves them once at construction and fills the gaps
with a refusal naming the backend, so every field on a `DB` is non-nil and a
missing capability reports `ErrUnimplemented` instead of panicking somewhere far
from the wiring that caused it.

| | Driver | Tx | Migrator | Batcher | Watcher | Graph | Series |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **orm** (SQL) | ✅ | ✅ | ✅ | — | — | — | — |
| **mongodb** | ✅ | ✅ | ✅ | ✅ | ✅ | — | — |
| **redis** | ✅ | — | ✅ | ✅ | — | — | — |
| **arangodb** | ✅ | ✅ | ✅ | ✅ | — | ✅ | — |
| **timescale** | ✅ | ✅ | ✅ | — | — | — | ✅ |
| **neo4j** | ✅ | ✅ | ✅ | — | — | ✅ | — |

The split is by what a backend can do, not by what it is called. GORM and
MongoDB are the closest pair here despite one being SQL and the other not;
Redis and MongoDB are the furthest apart despite both being "NoSQL". Grouping
by family would separate the two that behave alike and join the two that do
not.

## Transactions

`Tx.Run` hands the body a whole `DB`, not just the CRUD half, so a transaction
reaches everything the backend can do:

```go
db.Tx.Run(ctx, func(tx *database.DB) error {
    if _, err := tx.Create(ctx, userRes, alice); err != nil {
        return err
    }
    _, err := tx.Graph.Connect(ctx, memberRes, aliceRef, acmeRef, nil)
    return err
})
```

On a backend that is both a record store and a graph, creating a record and the
edges that join it is one operation or it is nothing.

## Graphs

A graph is a second axis over the same records, not a different contract.

```go
db.Graph.Connect(ctx, followsRes, aliceRef, bobRef, &pb.Follows{Since: ts})

edges, _ := db.Graph.Neighbors(ctx, aliceRef, database.TraverseOptions{
    Types: []string{"Follows"}, Direction: database.Outbound,
})
users, _ := database.Resolve[*pb.User](ctx, db, reg, database.Ends(edges))
```

Edge types are `Resource`s too — an ArangoDB edge collection and a Neo4j
relationship type are both "a thing with fields", so the same generated
descriptors describe them and edge properties need no second schema language.

Loading the records a walk found is a separate call, because "what is connected
to this" is one query and "load everything it is connected to" is one more per
record.

## Connection pools

The pool is what decides what happens under load, and every default here is a
starting point rather than an answer.

Where a provider takes a client you built — `orm`, `timescale`, `redis` — sizing
it is yours, on the client, before you hand it over:

```go
sql, _ := gormDB.DB()
sql.SetMaxOpenConns(50)
sql.SetMaxIdleConns(25)
sql.SetConnMaxLifetime(30 * time.Minute)
```

Where a provider builds the client, its `Config` carries the settings:

```go
mongodb.Config{Address: "…", MaxPoolSize: 200, MinPoolSize: 20}
arangodb.Config{Endpoints: […], MaxConnsPerHost: 200, MaxIdleConnsPerHost: 50}
```

Two defaults worth knowing because they fail quietly:

- **MongoDB caps at 100 connections per server** and *queues* past that rather
  than failing, so a service above that concurrency sees latency climb with no
  error to point at.
- **ArangoDB inherits Go's HTTP defaults** — unlimited connections and *two*
  idle. The first lets a burst exhaust the server's descriptors; the second
  makes every request past the second pay a fresh handshake.

## Time series

`Series` partitions a resource by time and reduces over it — the part of
TimescaleDB that is not already PostgreSQL:

```go
db.Schema.EnsureSchema(ctx, res)
db.Series.EnsureHypertable(ctx, res,
    timescale.PartitionedBy(timescale.Daily, "observed_at"))

buckets, _ := db.Series.Aggregate(ctx, res, database.AggregateOptions{
    TimeColumn: "observed_at",
    Every:      time.Hour,
    Reduce:     []database.Reduction{{Func: database.Avg, Column: "celsius"}},
    GroupBy:    []string{"device"},
})
```

The reduction runs in the database. Pulling a month of rows across the wire to
average them in Go is what a time-series store exists to stop, and it is what a
caller writes when the contract gives it no way to say what it wanted.

SQL does not implement `Graph`. `Resource.FKs` makes it tempting, but a join and
a variable-depth traversal are not the same operation — `MaxDepth: 5` over a
join table is an outage, not a slow query.

## Caching

[`cached`](./cached) puts a read-through cache in front of any driver, so a
record read repeatedly is fetched from the backing store once:

```go
db = cached.Wrap(db, cached.FromAside(cacheDB))
```

Concurrent misses on one key collapse into a single load, an absence is
remembered, and every write invalidates what it wrote — including writes
committed inside a transaction.

## Adding a backend

Implement [`Driver`](./driver.go) — seven methods over `proto.Message` — plus
whichever of the capability interfaces in [`capabilities.go`](./capabilities.go)
and [`graph.go`](./graph.go) your server has. The shared mechanics (generated
keys, audit timestamps, page tokens) live in [`core`](./core) so no driver
writes them again.
